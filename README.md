# D0 Bench

Репозиторий нормативных документов и артефактов сравнительного стенда `D0 Bench` —
программы экспериментов для выбора физической топологии неизменяемого корневого слоя
D0 Геометрического звукового протокола.

Стенд отвечает не на вопрос "какая схема выглядит красивее", а на вопрос: какая из
четырёх обязательных топологий (`D0-B1`, `D0-T2`, `D0-T3`, `D0-F3`) при одинаковом
энергетическом и пиковом бюджете надёжнее всего сохраняет логические формы D0, не
создаёт ложных записей, оставляет пространство для будущих suite и воспроизводимо
работает в чистом цифровом канале, после локальных искажений и после реального
перекодирования YouTube.

## Текущий статус

**T0 CANDIDATE PASS.** Шаг T0 (сборка, независимая проверка и заморозка девяти
нормативных бинарных DSP-таблиц) завершён и задокументирован в
[`T0_OUTPUT/T0_REPORT.md`](T0_OUTPUT/T0_REPORT.md).

- `d0_bench_integer_dsp_semantics_v1_7.md` остаётся статусом **DRAFT** — не изменён
  и не объявлен NORMATIVE.
- M0 (независимая реализация) **не начат**. `src/d0bench`, CLI, синтез, декод,
  сканер и прочие рантайм-компоненты в этом репозитории намеренно отсутствуют:
  их создание на шаге T0 запрещено правилами самого протокола.
- Следующий шаг — внешний red-team / review spec package перед выпуском
  NORMATIVE-версии companion и стартом M0.

## Spec package T0 (`T0_OUTPUT/`)

Девять замороженных нормативных бинарных таблиц (`int64` little-endian, two's
complement) плюс их закрытый JCS-манифест и полный отчёт проверки:

| table_id | dimensions | q_format | entry_count | bytes |
|---|---|---|---|---|
| `H_1000_999` | [1000, 25] | 30 | 25000 | 200000 |
| `H_147_160` | [147, 27] | 30 | 3969 | 31752 |
| `H_160_147` | [160, 25] | 30 | 4000 | 32000 |
| `H_999_1000` | [999, 25] | 30 | 24975 | 199800 |
| `H_DRIFT_Q30` | [1024, 25] | 30 | 25600 | 204800 |
| `ICDF_Q24` | [65536] | 24 | 65536 | 524288 |
| `PINK_V1` | [3, 5] | 30 | 15 | 120 |
| `SIN48000_Q30` | [48000] | 30 | 48000 | 384000 |
| `TP_FIR_Q30` | [4, 12] | 30 | 48 | 384 |

Инвариант `sum(entry_count * 8) == 1577144` подтверждён.

- [`T0_OUTPUT/dsp_tables_manifest.json`](T0_OUTPUT/dsp_tables_manifest.json) — закрытая схема, канонические JCS-байты.
- [`T0_OUTPUT/T0_REPORT.md`](T0_OUTPUT/T0_REPORT.md) — полный аудиторский отчёт: идентичность входов, blind
  transcription evidence, метод и результат двух независимых evaluator на каждую
  запись каждой генерируемой таблицы, глобальный инвариант размера, проверка
  манифеста, побайтовая воспроизводимость (clean rebuild), состав инструментария.
- [`T0_OUTPUT/TP_FIR_SOURCE_DECIMAL.txt`](T0_OUTPUT/TP_FIR_SOURCE_DECIMAL.txt) — побайтовая копия канонического источника.

## Offline-инструментарий (`T0_WORK/`)

Вспомогательный tooling шага T0 — **не** `src/d0bench` и **не** reference
implementation; отделён от будущего рантайм-кода и сохранён для аудита:

- `T0_WORK/scripts/` — генераторы таблиц и сборщик манифеста (Python 3.12 +
  `mpmath==1.4.1`, единственная внешняя зависимость).
- `T0_WORK/scripts_rebuild2/` + `T0_WORK/rebuild2_output/` — изолированная
  независимая пересборка для проверки побайтовой воспроизводимости (9/9 бинарников
  и манифест совпали побайтово со сборкой 1).
- `T0_WORK/logs/`, `T0_WORK/logs_rebuild2/` — журналы обеих оценок для каждой
  таблицы.
- `T0_WORK/venv/` в репозиторий не включён (см. `.gitignore`) — воспроизводится
  командой `pip install mpmath==1.4.1`.

Каждая генерируемая (`GENERATED_REAL`) таблица построена и подтверждена **двумя
независимыми offline-оценщиками** — интервальной арифметикой (`mpmath.iv`) и
процедурой сходимости на точности P/2P (`mpmath.mp`) — с нулевым расхождением по
каждой записи; методология и точные команды воспроизведения приведены в
`T0_OUTPUT/T0_REPORT.md`, раздел H.
