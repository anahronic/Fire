## 1. Округление и Q-форматы

Области округления разделены, и это снимает прежнее внутреннее противоречие: правило РАНТАЙМА одно — round half away from zero; правило ОФЛАЙН-ГЕНЕРАЦИИ замороженных таблиц данных — round half to even там, где это явно указано. Рантайм никогда не пересчитывает таблицы, поэтому два правила не встречаются в одном пути.

```text
round_shift(x, s):            # x целое, s >= 1
    h = 1 << (s - 1)
    if x >= 0: return (x + h) >> s
    else:      return -(((-x) + h) >> s)
```

Второй нормативный примитив — точное округление дроби:

```text
round_ratio(num, den):
    require den != 0
    if den < 0: num, den = -num, -den
    q, r = divmod(abs(num), den)
    if 2*r >= den: q += 1
    return q if num >= 0 else -q
```

Обязательные векторы: (7,2)->4, (-7,2)->-4, (5,-2)->-3, (1,3)->0, (2,3)->1, (-1,2)->-1.

Q-форматы: Q30 для таблиц (диапазон значений включает ровно ±2^30 как ±1.0; хранение — знаковое 64-битное), Q23 для PCM (S24 трактуется как Q23). Аккумуляторы: объявленная ширина 128 бит; выход за ±(2^127 − 1) — `ARITHMETIC_OVERFLOW`, не wrap. Никакое промежуточное округление не допускается, если оно не выписано явно ниже.

## 2. Канонический WAV v1

Единственное допустимое байтовое представление; любой другой корректный WAV не является каноническим:

```text
"RIFF" u32le(36 + data_size) "WAVE"
"fmt " u32le(16) u16le(1) u16le(1) u32le(48000)
       u32le(144000) u16le(3) u16le(24)
"data" u32le(data_size)
далее сэмплы: S24 little-endian two's complement, mono
```

Ровно 44 байта заголовка; никаких других chunks (JUNK, LIST, fact — запрещены); `data_size = 3 * N`; для токена `N = 48000`. Writer и reader обязаны отвергать неканонические файлы в нормативном пути.

## 3. Фаза и синус

Интерполяции НЕТ. Так как каждая несущая публичного профиля имеет целое число циклов в секунду при fs = 48000, фазовый индекс точен на решетке 1/48000 цикла:

```text
k(n, f_hz, phi_idx) = (n * f_hz + phi_idx) mod 48000
```

`phi_idx` — целочисленное представление фазы: индекс на той же решетке, диапазон 0..47999, нулевая фаза = 0. Это единственное нормативное представление фазы; выход фазового оптимизатора — вектор `phi_idx` по несущим; лексикографический порядок сравнения кандидатных фазовых векторов — по возрастанию индекса несущей.

Нормативная таблица `SIN48000_Q30[k]`, k = 0..47999, значения Q30. Хранится и хешируется полная таблица; допускается реализация через четвертную (12001 записей, включая оба конца) с отображением:

```text
q = k // 12000; r = k mod 12000
q=0: +T[r]      q=1: +T[12000-r]
q=2: -T[r]      q=3: -T[12000-r]
```

Генерация таблицы: вычисление sin(2*pi*k/48000) по единому критерию таблиц §14, округление round half to even до Q30 (офлайн-правило §1); таблица публикуется как данные с SHA-256 и с этого момента является замороженным артефактом наравне с оконными таблицами протокола. Точные якоря, обязательные независимо от генератора:

```text
SIN48000_Q30[0]     = 0
SIN48000_Q30[4000]  = +536870912      # sin 30 градусов = 1/2 точно
SIN48000_Q30[12000] = +1073741824     # ровно +1.0
SIN48000_Q30[24000] = 0
SIN48000_Q30[36000] = -1073741824
```

## 4. Синтез сэмпла

Порядок операций и оба места округления фиксированы:

```text
acc = сумма по несущим j:  amp_q30[j] * SIN48000_Q30[k(n, f[j], phi[j])]
                            # каждое слагаемое Q60; acc 128-bit
y1  = round_shift(acc, 30)                  # Q30
y2  = round_shift(y1 * W_Q30[n], 30)        # Q30, окно кандидата
pcm = sat24(round_shift(y2, 7))             # Q30 -> Q23 (S24)
```

Никаких иных округлений.

Сборка копий фиксирована. Каждая последовательная diagnostic subform (`T2`, `T3`) синтезируется на ЛОКАЛЬНОМ индексе `n_local = 0..N_copy-1` со своим окном длины `N_copy`; assembled форма есть конкатенация уже синтезированных subform-выходов, без повторного округления. Для `D0-F3` слагаемые всех трех одновременных копий входят в один `acc` на глобальном `n = 0..47999`, окно применяется один раз.

Периодичность копий — обязательная валидация манифеста кандидата: для каждой периодической копии длины `N_copy` каждая несущая обязана удовлетворять `(N_copy * f_hz) mod 48000 == 0` (целое число циклов на области анализа копии: для `N=24000` f четно, для `N=16000` f кратно 3). Нарушение — отказ манифеста до синтеза, статус `INVALID_MANIFEST`.

## 5. True peak

Передискретизация x4, полифазный FIR: 4 фазы по 12 коэффициентов. Нормативная таблица `TP_FIR_Q30[4][12]` НЕ проектируется реализатором: принимаются опубликованные коэффициенты фильтра истинного пика ITU-R BS.1770-5, Annex 2 (order 48, 4-phase, FIR interpolating), преобразованные в Q30 офлайн-правилом round half to even. Ориентация привязана к печатной таблице источника, а не к словам "первый" и "последний": `TP_FIR_Q30[p][i]`, где `p = 0..3` есть номер столбца `Phase p` слева направо, а `i = 0..11` есть номер строки таблицы сверху вниз. Для автономности T0 сами 48 исходных десятичных литералов переносятся в spec package отдельным файлом `TP_FIR_SOURCE_DECIMAL.txt`, а ITU-R BS.1770-5 остается ссылкой на происхождение: T0 не зависит от разбора PDF, доступности сайта и типографских различий знака минус.

Байтовое представление `TP_FIR_SOURCE_DECIMAL.txt` нормировано, поскольку SHA-256 этого файла является частью идентичности spec package. Редакция 1.5 фиксировала только порядок, десятичный разделитель и ASCII-минус, чего для побайтовой идентичности недостаточно: две добросовестные транскрипции одних и тех же величин давали разные байты:

```text
encoding: ASCII, совпадающий с UTF-8 на ASCII subset
BOM: запрещен
line separator: LF (0x0A); байт CR (0x0D) запрещен
48 logical lines, ровно один литерал на строку
порядок строк: phase-major, сначала p, затем i
пустые строки, ведущие и хвостовые пробелы запрещены
завершающий LF после строки 48 отсутствует
формат литерала: необязательный "-", затем "0", затем ".",
    затем РОВНО 13 десятичных цифр
знак: только ASCII "-" (0x2D); "+" запрещен
экспоненциальная запись запрещена
число знаков источника не сокращается: 13 цифр после точки,
    включая хвостовые нули, как напечатано в Annex 2
```

Замороженная идентичность файла:

```text

проверка    48 logical lines, LF = 47, CR = 0, BOM absent, trailing LF absent
```

Этот файл является нормативным артефактом spec package, но НЕ является записью `dsp_tables_manifest.json`: схема раздела 14 закрыта, ее `element_type` есть `int64_le_twos_complement`, а `entry_count` обязан равняться `размер_файла / 8`, и текстовый файл ни одному из этих условий не удовлетворяет. Инвариант суммарного размера раздела 14 считается только по девяти бинарным таблицам. Носителем нормативной идентичности `TP_FIR_SOURCE_DECIMAL.txt` является приведенный выше блок, то есть текст самого companion, и далее SHA-256 companion через объект `dsp_semantics_reference.json`. Добавлять для него поле или запись в манифест таблиц ЗАПРЕЩЕНО: это изменило бы закрытую схему и `tables_manifest_sha256`.

Проверочные значения транскрипции вычислены из зафиксированного файла точной рациональной арифметикой. Все 48 литералов имеют знаменатель, делящий `8192`, поэтому умножение на `2^30` дает целое без остатка: halfway case на этих данных отсутствует, и правило round half to even, оставаясь нормативным, ни разу не срабатывает. Класс происхождения остается `IMPORTED_EXACT`: приведенный блок является проверкой, а не источником. Независимая сторона обязана сверять `TP_FIR_SOURCE_DECIMAL.txt` с самим документом ITU, а не с этим companion; сверка с companion воспроизводит транскрипцию вместо того, чтобы ее проверять. Проверка выполняется внутри T0 и до записи `TP_FIR_Q30.bin`, вслепую: проверяющий получает только документ ITU и правило порядка (столбец `Phase p` слева направо, строка сверху вниз), а файл и его SHA-256 ему показывают после того, как его собственный результат зафиксирован. Отдельного gate перед T0 для этого не вводится.

Структурные инварианты обязательны как дешевая проверка порядка и на данных источника выполняются точно:

```text

TP_FIR_Q30[2][i] == TP_FIR_Q30[1][11 - i]   для всех i
sum |TP_FIR_Q30[0][*]| == sum |TP_FIR_Q30[3][*]| == 1539964928
sum |TP_FIR_Q30[1][*]| == sum |TP_FIR_Q30[2][*]| == 2171994112
```

Из этих же симметрий следует граница возможностей поведенческих тестов, и формулировка редакции 1.5 о том, что раскладку ловит golden-вектор, была слишком сильной. Транспонированная раскладка `[12][4]` действительно ловится golden-вектором на несимметричном входе, потому что дает другой набор коэффициентов. Но реверс порядка отводов внутри фазы, `H'[p][i] = H[p][11 - i]`, по указанной симметрии тождественно равен перестановке фаз `(0 3)(1 2)`, а `true_peak_q` есть максимум по всем `(n, p)` и от перестановки фаз не зависит. Поэтому реверс отводов НЕ обнаруживается ни одним тестом на выходе true peak и ловится только побайтовым сравнением `TP_FIR_SOURCE_DECIMAL.txt` и `TP_FIR_Q30.bin` с зафиксированными выше SHA-256. По той же симметрии двойной реверс `(p, i) -> (3 - p, 11 - i)` дает побитово тот же файл и потому безвреден.

Диапазон выходных позиций задан явно, потому что без него две реализации получают разные значения на сигнале, не спадающем к нулю на краях, то есть на любом наблюдении после кодека, лимитера, gain или ресемплера. При `N` входных сэмплах и нулевом дополнении по 11 сэмплов с каждой стороны единственные позиции с ненулевым вкладом суть `n = 0 .. N + 10`, что дает `4 * (N + 11)` выходов; для токена `N = 48000` это `n = 0..48010` и 192044 выхода. Для каждого такого `n` и каждой фазы `p`:

```text
acc = сумма i=0..11: TP_FIR_Q30[p][i] * x_q23[n + i - 11]
      # x_q23[k] = 0 при k < 0 и при k >= N
v   = |round_shift(acc, 30)|            # abs после округления; 64-bit,
                                        # MIN не достижим по построению
true_peak_q = max по всем (n, p) из v   # в Q23-шкале, единичное усиление
n   = 0 .. N + 10
```

Шаг источника `attenuate 12.04 dB` и обратная компенсация 12.04 dB НЕ применяются. В ITU-R BS.1770-5 это средство создания headroom для целочисленной реализации, которое затем нормируется обратно к единичному усилению; здесь аккумулятор объявлен 128-битным и арифметика точна, поэтому оба шага сокращаются тождественно, а их буквальное исполнение внесло бы потерю точности на двухбитном сдвиге. Реализация, применившая аттенюацию буквально, даст другое значение и провалит crosscheck; это запрещено явно, а не оставлено на усмотрение. Поэтому `true_peak_q` уже выражен в единичном масштабе Q23 и сравнивается с `true_peak_limit_q` протокола напрямую, без поправки.

Насыщение к `v` и к `true_peak_q` НЕ применяется. Сумма модулей коэффициентов фазы больше единицы, поэтому истинный пик законно превышает full scale, и ограничение результата до 8388607 является дефектом, скрывающим ровно тот overshoot, ради обнаружения которого измерение и существует. Источник утверждает то же самое: истинный пик может быть выше наибольшего отсчета, а компенсация 12.04 dB в общем случае требует числового формата, способного представлять значения выше full scale исходного.

Достижимая граница и аналитическая граница различаются, и подменять одну другой запрещено. Диапазон S24 несимметричен, `-8388608 <= x_q23 <= 8388607`, поэтому произведение `sum|h| * 8388608` недостижимо: оно требовало бы отсчета `+8388608`, которого в S24 нет. Точная достижимая граница берется по вершине бокса, где положительные коэффициенты умножаются на один край диапазона, а отрицательные на другой. Для фаз 1 и 2, где `сумма h>0 = 1608384512` и `сумма |h<0| = 563609600`:

```text
достижимый max |acc|       = 18220006620266496   # 1608384512 * 8388608
                                                 # + 563609600 * 8388607
                                                 # bit_length 55, то есть < 2^55
достижимый max true_peak_q = 16968703            # round_shift(.., 30);
                                                 # одинаково для обоих знаков acc
аналитическая верхняя граница true_peak_q <= 16968704, недостижима
```

Для фаз 0 и 3 достижимый максимум равен 12030976. В boundary assertion допустимо использовать только `16968703`; проверка на равенство `16968704` даст ложный отказ корректной реализации.

Групповая задержка не компенсируется: пик есть максимум по всем выходам. `sample_peak_q = max |x_q23[n]|` по `n = 0..N-1`.

## 6. Решатель Gram

Точная целочисленная схема: fraction-free элиминация Барейса, одно округление на выходе.

```text
solve_gram_q(G, b, out_shift):
    # G: KxK целые (масштаб манифеста), b: K целых
    A = [G | b]  расширенная, все целые
    prev = 1
    for col in 0..K-1:
        pivot_row = наименьший r >= col с A[r][col] != 0
        если нет -> GRAM_INVALID
        swap(col, pivot_row)              # детерминированный выбор
        for r in col+1..K-1:
            for c in col+1..K:
                A[r][c] = (A[col][col]*A[r][c] - A[r][col]*A[col][c]) // prev
            A[r][col] = 0
        prev = A[col][col]
    det = A[K-1][K-1];  если det == 0 -> GRAM_INVALID
    обратный ход в точных дробях (num, den) над det
    coeff_q[i] = round_ratio(num_i << out_shift, den_i)
                 # round half away from zero знака дроби
```

Деление Барейса точное по построению (свойство алгоритма). Порог condition — по манифесту, сравнение точными дробями. Обязательные векторы: диагональная матрица; коррелированная; требующая перестановки; нулевой pivot в первой строке; сингулярная; результат в ±1 LSB от порога решения; предельные значения аккумулятора.

## 7. PRNG и DISCRETE_GAUSSIAN_U16

Поток: SHA-256 в режиме счетчика.

```text
block(seed32, ctr) = SHA256( LP("D0BENCH-AWGN-V1") || seed32 || u64be(ctr) )
u16(sample_i): ctr = i // 16;  off = 2*(i mod 16)
               big-endian из байтов [off, off+2) блока
```

Гауссово отображение: замороженная таблица `ICDF_Q24[65536]` — обратная нормальная CDF в средних точках `(u + 0.5)/65536`, Q24; офлайн-генерация алгоритмом Wichura AS241 по единому критерию §14: сертифицированная абсолютная ошибка < 0.25 ULP целевого Q24 (то есть < 2^-25) до round half to even, что привязывает требование к конечной таблице, а не к свойствам библиотеки; публикация с SHA-256 на шаге T0. Нормативное имя пробы — `DISCRETE_GAUSSIAN_U16`, а не AWGN: хвосты усечены концами таблицы на |z| = 4.3249 сигма (вероятность хвоста 0.5/65536 на каждую сторону), и любое утверждение о непрерывном гауссовом канале для этой пробы запрещено. Это часть определения пробы; все кандидаты получают одну и ту же дискретную модель. Каждая ячейка с этой пробой обязана публиковать `saturation_count` — число сэмплов, где sat24 сработал; отчет различает ячейки с нулевым и ненулевым счетчиком, потому что при насыщении граница отказа частично является границей клиппинга, а не шума.

```text
noise_q23(i) = sat24(round_shift(sigma_q30 * ICDF_Q24[u16(i)], 31))
y[n] = sat24(x[n] + noise_q23(n))
```

Замороженный вектор (seed = 32 нулевых байта, ctr = 0):

```text
block0 = 78adece768f2904ce6b98a577a92db9da14f7afd6c3520cb8237d04032fa214c
первые четыре u16 = 30893, 60647, 26866, 36940
```

Seed-дерево ячейки: `seed_cell = SHA256(LP("D0BENCH-CELL-SEED-V1") || experiment_seed32 || LP(cell_id))`.

## 8. Notch и tilt: биквад

Direct Form I, не транспонированная; состояния — сохраненные S24-выходы; начальные состояния нулевые:

```text
acc = b0*x[n] + b1*x[n-1] + b2*x[n-2]
      - a1*y[n-1] - a2*y[n-2]          # коэффициенты Q30, x,y как Q23
y[n] = sat24(round_shift(acc, 30))
```

Одно округление на выход; acc 128-bit; знаковая конвенция — как выписано (a-члены вычитаются). Коэффициенты — из таблиц манифеста ячейки. Tilt реализуется этим же примитивом с другой таблицей.

## 9. Ресемплер

Rational polyphase, нормативная функция:

```text
resample(x, L, M, H_Q30, phase0 = 0)
    # 48000->44100: L=147, M=160;  обратно: L=160, M=147
    t(m) = m*M + phase0                    # позиция в up-решетке
    y[m] = round_shift( сумма i: H_Q30[..] * x[..], 30 ), sat24
    N_out = ceil(N_in * L / M)             # ceil_div
```

Пары отношений нормативны: 48000<->44100 это 147/160 и 160/147; 48000<->47952 это 999/1000 и 1000/999, каждая пара со СВОЕЙ таблицей `H_Q30`, задержкой, формулой длины и round-trip вектором. Полифазное разложение фиксировано: `y[m]` использует фазу `t(m) mod L` и входные индексы `floor(t(m)/L) - i`. Каждая `H_Q30` — замороженная таблица с SHA-256 (шаг T0); проект прототипа задан полностью воспроизводимой процедурой: длина `N_h = 24 * max(L, M) + 1` (нечетная), центр `c = (N_h - 1) / 2`; идеальный отклик `h_id[n] = sin(omega * (n - c)) / (pi * (n - c))` при `n != c`, `h_id[c] = omega / pi`, `omega = pi * (9/10) * min(1/L, 1/M)`; окно Кайзера `w[n] = I0(beta * sqrt(1 - ((n - c)/c)^2)) / I0(beta)`, beta = 12, `I0(x) = sum_k ((x/2)^k / k!)^2` с обрывом ряда, когда очередной член < 2^-100; НОРМИРОВКА: масштаб `s = L / sum_n(h_id[n] * w[n])` применяется в высокой точности ДО квантования, так что сумма полного фильтра равна ровно L (интерполяционный gain; сумма каждой фазы близка к 1); затем round half to even в Q30 по критерию §14. Полифазная раскладка ПРЯМОУГОЛЬНАЯ; ragged-массивы запрещены, потому что `N_h` не делится на `L` ни для одной нормативной пары, и без явного правила один коэффициент оказывался бы вне объявленной размерности:

```text
P = L
K = ceil_div(N_h, L)
H_Q30[p][i] = h[p + i * L], если p + i * L < N_h
              0,             иначе
dimensions = [P, K]

нормативные размерности:
    48000 -> 44100    L=147  M=160   N_h=3841    [147][27]
    44100 -> 48000    L=160  M=147   N_h=3841    [160][25]
    48000 -> 47952    L=999  M=1000  N_h=24001   [999][25]
    47952 -> 48000    L=1000 M=999   N_h=24001   [1000][25]
    drift             L=1024 M=1     N_h=24577   [1024][25]
```

Рантайм всегда суммирует `i = 0..K-1`; дополненные нулевые коэффициенты делают особый случай для отдельных фаз ненужным, а входные индексы за пределами сигнала дают ноль по правилу краевого дополнения. Нормировка этого раздела применяется к полному `h` длины `N_h` ДО квантования, поэтому дополнение нулями сумму не меняет. Нулевое краевое дополнение.

Сквозная задержка round trip определяется здесь, а не при T0 (T0 только вычисляет данные, не принимает инженерных решений): групповая задержка каждой стадии равна `c = (N_h - 1)/2` в апсемпл-решетке этой стадии; задержка стадии в ЕЕ выходных сэмплах равна `c / M`; перевод задержки первой стадии в финальную решетку — умножение на `L2 / M2`. Итого точная дробь `D_exact = (c1 * L2 + c2 * M1) / (M1 * M2)`, нормативный целочисленный сдвиг `D = round_ratio(c1 * L2 + c2 * M1, M1 * M2)`; `phase0 = 0` на обеих стадиях; выход round trip обрезается `[D, D + 48000)` с нулевым дополнением справа.

Дрейф частоты дискретизации — ОТДЕЛЬНАЯ проба, не сводимая к постоянному 47952 (тот дает лишь фиксированные -1000 ppm): манифест ячейки хранит `ppm_start_num/ppm_start_den`, `ppm_end_num/ppm_end_den` и `profile = CONSTANT | LINEAR_RAMP`; значения в ppm, физический относительный коэффициент включает 10^6 явно:

```text
delta(num, den) = num / (den * 1000000)
CONSTANT:     delta_n = delta(ppm_start_*) для всех n
LINEAR_RAMP:  delta_n = delta_start +
              (delta_end - delta_start) * n / (N_total - 1);
              при N_total = 1 -> delta_n = delta_start
step_n = 1 + delta_n
```

Позиция накапливается точной дробью с общим знаменателем `PD = ppm_start_den * ppm_end_den * 1000000 * max(1, N_total - 1)`: `pos(0) = 0`, `pos_num(m+1) = pos_num(m) + step_num(m)`, где `step_num(m)` — числитель `step_m` над `PD`, все члены целые. Отображение дробной позиции в ядро фиксировано: `idx = pos_num // pos_den`, `frac = pos_num mod pos_den`, фаза `p = (frac * 1024) // pos_den` (floor, монотонно) по выделенной таблице `H_DRIFT_Q30[1024][25]`, построенной процедурой прототипа этого раздела при L = 1024, M = 1 с той же прямоугольной раскладкой; выход

```text
y[m] = sat24(round_shift(
           sum_{i=0..24} H_DRIFT_Q30[p][i] * x[idx + 12 - i], 30))
```

с нулевым краевым дополнением. Направление индекса входа существенно и НЕ произвольно: при раскладке `H[p][i] = h[p + i*L]` коэффициент соответствует ядру в точке `(i - 12) + p/L`, а свертка интерполяции требует `sum_k x[k] * phi(idx + frac - k)`; подстановка `k = idx + 12 - i` дает ровно `(i - 12) + frac`. Обратный порядок `x[idx - 12 + i]` из-за симметрии ядра соответствовал бы позиции `idx - frac`: при росте `frac` от нуля почти до единицы интерполируемая позиция шла бы НАЗАД и скачком перескакивала вперед на переходе к следующему `idx`, то есть траектория дрейфа была бы разрывной. Обязательный golden-вектор проверяет фазы `p = 0, 256, 512, 768, 1023` на НЕСИММЕТРИЧНОМ входе (монотонный ramp либо асимметричный многосэмпловый вектор; на симметричном сигнале реверс не виден) и отдельно отсутствие искусственного скачка на переходе `(idx=100, p=1023) -> (idx=101, p=0)`. Round trip 48000 -> 44100 -> 48000 использует сквозную задержку `D`, определенную в этом разделе. Обязательный вектор: импульс в позиции 24000 после round trip.

## 11. Композиция преобразований и стерео-контракт

Трансформ-движок типизирован ДВУМЯ представлениями: `PCM_MONO_S24_48K` и `PCM_STEREO_S24_48K`; каждое звено объявляет вход и выход. Обязательные межканальные примитивы (все точные, покомпонентно по правилам §1):

```text
mono_to_dual_mono            # L = R = x
downmix                      # y = sat24(round_shift(L + R, 1))
swap_lr
channel_gain(gL_q30, gR_q30) # раздельно по каналам
channel_polarity(pL, pR)     # умножение на +-1
channel_delay(dL, dR)        # целые сэмплы, нулевое дополнение
opposite_phase_mix(a_q30)    # L' = sat24(L - rs(a*R,30)); R' симметрично
```

Полный обязательный набор классов G3 определяется channel-матрицей протокола, и движок обязан выражать КАЖДЫЙ класс; помимо уже определенных (шум, notch, burst, click, ресемплинг, кодеки, gain, tilt, MDCT-смещения) нормативно добавлены limiter, AGC и shaped-шумы (исполнимые контракты ниже), sample clipping (насыщение на заданном уровне ниже full scale), low-pass и high-pass (биквад §8 с таблицами), crop, insertion, deletion, mute burst, additive burst, drift (§9), и комбинированные цепочки (burst+notch, codec+gain+limiter, codec+спектральное повреждение) — как композиция уже определенных звеньев. Отсутствие в движке любого класса обязательной матрицы — блокер A3.

Контракты stateful-звеньев (уровень строгости биквада §8: порядок обновления состояний и все места округления фиксированы, начальные состояния заданы, lookahead отсутствует; для стерео детекторы СВЯЗАНЫ — общий `a = max(|L|, |R|)` и один g на оба канала, чтобы звено не искажало межканальные отношения, для которых существуют отдельные канальные пробы):

```text
limiter(T_q23, a_att_q30, a_rel_q30):        # peak-детектор
    env = 0; g = 1 << 30
    для каждого n (состояния обновляются ДО выхода, на текущем сэмпле):
        a = |x[n]|
        env = a, если a > env, иначе round_shift(a_rel_q30 * env, 30)
        g_t = round_ratio(T_q23 << 30, env), если env > T_q23,
              иначе 1 << 30
        d = g - g_t
        g = g_t + round_shift((a_att_q30 если d > 0 иначе a_rel_q30) * d, 30)
        y[n] = sat24(round_shift(x[n] * g, 30))

agc(target_q23, a_env_att_q30, a_env_rel_q30, a_gain_q30,
    g_min_q30, g_max_q30):                    # peak-детектор
    env = 0; g = 1 << 30
    для каждого n:
        a = |x[n]|
        c = a_env_att_q30, если a > env, иначе a_env_rel_q30
        env = env + round_shift(c * (a - env), 30)
        g_t = clamp(round_ratio(target_q23 << 30, env),
                    g_min_q30, g_max_q30), если env > 0, иначе g_max_q30
        g = g + round_shift(a_gain_q30 * (g_t - g), 30)
        y[n] = sat24(round_shift(x[n] * g, 30))

розовый и shaped шум: поток §7 пропускается через каскад биквадов §8
    (порядок секций = порядок списка; состояния нулевые), затем
    прибавляется к сигналу как в §7. Фильтры — НОРМАТИВНЫЕ КОНСТАНТЫ,
    а не предмет офлайн-дизайна; набор V1 состоит из PINK_V1:

    PINK_V1, три секции первого порядка (b2 = a2 = 0), Q30,
    единичный модуль на 1000 Гц, наклон около -3 дБ/окт в 100..10000:
        секция 0: b0 = 2631693208  b1 = -2597467940  a1 = -1069306727
        секция 1: b0 =  353978446  b1 =  -310430765  a1 = -1030194144
        секция 2: b0 =  429140238  b1 =   -56497384  a1 =  -701098970
    Иные shaped-профили добавляются только новой версией companion.

sample_clipping(T_q23): y[n] = clamp(x[n], -T_q23, +T_q23),
    симметрично, T_q23 <= 8388607

crop(start, length): выход = x[start .. start+length), сдвинут к нулю,
    справа нулевое дополнение до 48000; итоговая длина ВСЕГДА 48000

insertion(pos, ins_len, pattern_id | ZEROS): в позицию pos вставляется
    ins_len сэмплов (нули либо S24-паттерн таблицы), затем ПРАВЫЙ край
    обрезается до 48000

deletion(pos, del_len): удаляется [pos, pos+del_len), остаток
    сдвигается влево, справа нулевое дополнение до 48000

mute burst: синоним burst-стирания §10 (одно определение, два имени)

additive burst(a, b, pattern_id): y[n] = sat24(x[n] + P[n - a])
    на [a, b), P — S24-паттерн таблицы; за пределами не меняется

channel_delay(dL, dR): d >= 0 целые сэмплы; d > 0 ЗАДЕРЖИВАЕТ канал:
    y[n] = x[n - d] при n >= d, иначе 0; длина остается 48000, хвост
    за 48000 отбрасывается; отрицательные d запрещены, опережение
    выражается задержкой другого канала

opposite_phase_mix(a_q30): вычисляется из СНИМКА исходных L, R
    одновременно: L' = sat24(L - round_shift(a_q30 * R, 30)),
    R' = sat24(R - round_shift(a_q30 * L, 30)); in-place реализация,
    использующая уже измененный L' при расчете R', неверна и ловится
    golden-вектором с несимметричной парой
```

Промежуточное представление между звеньями цепи — S24 @ 48000 в памяти объявленного типа; WAV между звеньями не пишется. Кодек-звенья: encode из канонического WAV во временный контейнер, decode пинованным ffmpeg в raw s24le, длина приводится к 48000 обрезкой/нулевым дополнением справа (сдвиг кодека компенсируется по задокументированному в env_manifest праймингу конкретного кодека). Насыщение — на выходе каждого звена, как задано его формулой.

## 12. Сканер: NMS и планирование

```text
тайлы: полуоткрытые [k*T, (k+1)*T), пик принадлежит тайлу по началу
локальный максимум через плато: максимальный run равных значений [a,b]
    является пиком, если score[a] > score[a-1] и score[b] > score[b+1]
    (края дорожки считаются минус бесконечностью);
    representative index = a
NMS: строго ВНУТРИ тайла и внутри роли, по протоколу; пики разных
    тайлов НЕ подавляют друг друга и не сравниваются на этой стадии
ключ пика: (score убыв, time возр, role_id возр)
cross-tile дедупликация: ТОЛЬКО отчетная разметка (reporting-only
    aliasing) — гипотезы одной роли с |dt| <= R получают общий
    diagnostic alias_id; разметка НЕ меняет множество гипотез,
    оценку grammar, счетчики false-accept, расход ресурсов и ни одну
    научную метрику; протокол merge-стадии не определяет, поэтому
    влияние на evidence было бы его изменением
пулы бюджетов типизированы и неперераспределяемы:
    BEACON, BOOT, FULL_BOUNDARY, OPAQUE, CROSS_FAMILY;
    отдельно минимальная квота на тайл; OPAQUE не может
    расходовать BEACON ни при каких условиях
stage 2: round-robin по тайлам с тайла 0 по возрастанию;
    пустой тайл пропускается, НЕ расходуя ничего
квота пула расходуется в момент создания гипотезы;
    rank-up квоту не возвращает
eviction при переполнении пула: удаляется минимальный ключ
    (rank возр, score возр, time убыв)
emit: (time возр, role_id возр, hypothesis_id возр)
```

Обязательные golden-случаи: пик ровно на границе тайла (принадлежит правому и НЕ подавляет пик левого); два равных пика (плато, representative ранний); три равных; пара гипотез через границу тайлов, получающая общий alias_id при неизменных гипотезах, счетчиках и квотах; попытка расхода BEACON из OPAQUE (обязана отказать); исчерпание бюджета ровно на последней гипотезе; rank promotion на последней квоте; отмена между стадиями.

## 13. Подписанные записи переходов

```text
            JCS(запись перехода без поля signature)
signature = Ed25519(message), 64 байта, hex нижним регистром
key_id    = первые 16 hex SHA-256 от 32-байтового публичного ключа
```

## 14. Реестр golden-векторов

Каждый примитив разделов 1-13 имеет векторный набор в `vectors/dsp/`; A0 не считается пройденным без побитового совпадения всех наборов в обеих реализациях границы crosscheck.

Таблицы делятся на три класса происхождения, и критерий точности применяется только к первому, потому что остальные два не вычисляются, а переносятся:

```text
GENERATED_REAL: SIN48000_Q30, ICDF_Q24, H_147_160, H_160_147,
                H_999_1000, H_1000_999, H_DRIFT_Q30
    -> два независимых офлайн-оценщика, сертифицированная
       ошибка < 0.25 ULP целевого Q-формата ДО округления;
       расхождение любых двух записей после округления — провал T0

IMPORTED_EXACT: TP_FIR_Q30
    -> точные десятичные литералы источника (раздел 5), точное
       десятичное или рациональное преобразование в Q30;
       независимая проверка транскрипции против документа ITU,
       а не пересчет фильтра и не сверка с этим companion;
       проверка порядка отводов ТОЛЬКО побайтовая по разделу 5,
       поведенческий golden-вектор реверс отводов не обнаруживает

EXACT_INTEGER: PINK_V1
    -> точные целые Q30 из раздела 11 копируются как есть;
       независимая проверка байтов и формы. T0 НЕ проектирует
       этот фильтр заново
```

Сертификация ошибки для класса GENERATED_REAL определена, а не подразумевается: минимум один из оценщиков обязан использовать интервальную арифметику ЛИБО процедуру сходимости (вычисление на точности P и 2P; результат после округления неизменен и явная граница ошибки < 0.25 ULP показана), поскольку совпадение двух неверифицированных высокоточных результатов само по себе границу не доказывает.

Идентичность набора таблиц задается нормативным объектом `dsp_tables_manifest.json`:

```text
{ "schema_version": 1,
  "tables": [ { "table_id": "...",        # только ASCII
                "filename": "...",
                "element_type": "int64_le_twos_complement",
                "dimensions": [...],
                "q_format": ...,
                "entry_count": ...,
                "sha256": "..." } ] }

порядок tables[] — строго по возрастанию table_id побайтово (UTF-8;
    при ASCII-ограничении это же порядок UTF-16 code units)

tables_manifest_sha256 = SHA256(
    LP("D0BENCH-DSP-TABLES-MANIFEST-V1") ||
    LP(JCS(dsp_tables_manifest)) )
```

Только эта величина пинуется полем `tables_manifest_sha256` объекта `dsp_semantics_reference.json`.

Хеш от JCS-объекта сам по себе НЕ дает побайтовой идентичности десятого файла: два исполнителя могут получить один `tables_manifest_sha256` при разном форматировании файла. Поэтому байты файла тоже нормированы:

```text
байты dsp_tables_manifest.json = JCS(dsp_tables_manifest)
UTF-8, без BOM, без завершающего LF или CRLF,
без пробелов и переводов строк вне результата JCS
```

Схема закрыта: в корне разрешены РОВНО `schema_version` и `tables`; в каждом entry РОВНО `table_id`, `filename`, `element_type`, `dimensions`, `q_format`, `entry_count`, `sha256`. Любое дополнительное поле — ошибка схемы. `sha256` — ровно 64 символа ASCII hex в нижнем регистре. `entry_count` равен произведению `dimensions` и одновременно `размер_файла / 8`, то есть считается ПОСЛЕ прямоугольного дополнения нулями: для `H_147_160` это 3969, а не 3841, поскольку сериализуются 3969 значений int64 включая дополненные нули.

Ожидаемый состав T0 заморожен здесь как проверочный инвариант; расхождение любой строки — провал T0:

```text
table_id        dimensions    q   entry_count      bytes
H_1000_999      [1000, 25]   30        25000     200000
H_147_160       [147, 27]    30         3969      31752
H_160_147       [160, 25]    30         4000      32000
H_999_1000      [999, 25]    30        24975     199800
H_DRIFT_Q30     [1024, 25]   30        25600     204800
ICDF_Q24        [65536]      24        65536     524288
PINK_V1         [3, 5]       30           15        120
SIN48000_Q30    [48000]      30        48000     384000
TP_FIR_Q30      [4, 12]      30           48        384

инвариант: sum(entry_count * 8) == 1577144
```

Строки приведены в нормативном порядке сортировки `table_id`, то есть в том же порядке, в котором они обязаны стоять в `tables[]`.

Помимо девяти бинарных таблиц spec package шага T0 содержит один нормативный текстовый артефакт происхождения. Он не входит в `tables[]`, не участвует в инварианте суммарного размера и имеет собственную замороженную идентичность по разделу 5:

```text
TP_FIR_SOURCE_DECIMAL.txt   789 байт
SHA-256 0935e97d0b2efd5fdb77826430e9dc161833b9c916585547d0d910b3cda37424
```

Имена файлов spec package шага T0 заданы здесь и больше нигде: девять бинарных таблиц по полю `filename` соответствующих записей `dsp_tables_manifest.json`, текстовый артефакт буквально как `TP_FIR_SOURCE_DECIMAL.txt` по разделу 5. Отдельного файла контрольных сумм шаг T0 не вводит; `checksums.sha256` протокола принадлежит дереву `publication/` и к spec package отношения не имеет. Логическое имя документа в его шапке может отличаться от имени файла на диске пунктуацией номера версии; нормативной является пара из SHA-256 и объекта `dsp_semantics_reference.json`, а не строка шапки.

Шаг T0 (сборка и заморозка таблиц) выполняется ДО начала какой-либо реализации: таблицы `SIN48000_Q30`, `TP_FIR_Q30`, `ICDF_Q24`, все `H_Q30`, `H_DRIFT_Q30` и таблицы каскадов shaped-noise собираются описанными офлайн-процедурами, независимо проверяются и сериализуются в бинарные файлы spec package. Сериализация задана буквально, поскольку SHA-256 файла является нормативной идентичностью:

```text
элемент: int64 little-endian, two's complement
многомерные таблицы: row-major, внешний индекс внешним циклом
    для p = 0..P-1:
        для i = 0..K-1:
            emit int64_le(H[p][i])
TP_FIR_Q30[4][12]: для p = 0..3, для i = 0..11
PINK_V1[3][5]: для секции s = 0..2 подряд b0, b1, b2, a1, a2
    (b2 и a2 равны нулю и присутствуют явно)
одномерные таблицы: по возрастанию индекса
```

Множество table_id заморожено, поскольку порядок `tables[]` определяется именно этими строками и иное написание изменило бы `tables_manifest_sha256`:

```text
H_1000_999      H_147_160      H_160_147      H_999_1000
H_DRIFT_Q30     ICDF_Q24       PINK_V1        SIN48000_Q30
TP_FIR_Q30
```

Имя файла таблицы равно `<table_id>.bin`. По завершении T0 выпускается СЛЕДУЮЩАЯ версия этого документа со статусом NORMATIVE, куда вписаны имя, размер, сериализация и SHA-256 каждой таблицы; версия со статусом DRAFT никогда не модифицируется после публикации ее хеша. A0 таблицы ТОЛЬКО ПРОВЕРЯЕТ по хешам и якорям — A0 их не выбирает и не порождает. До завершения T0 нормативной версии companion не существует, и публикация манифеста программы невозможна. Таблицы — общие нормативные ДАННЫЕ и передаются обеим независимым реализациям наравне со спецификацией; использование независимой стороной чего-либо, сгенерированного reference-реализацией и не опубликованного в spec package, запрещено.
